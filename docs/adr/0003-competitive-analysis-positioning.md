# ADR-0003: 競合フレームワーク分析と Broth のポジショニング

- **ステータス**: 承認済み
- **日付**: 2026-02-08

## コンテキスト

Go の Web フレームワークエコシステムにおいて、過去のフルスタック試行（Buffalo、Beego）の失敗要因を分析し、Broth が同じ轍を踏まないための設計指針を確立する必要があった。

## 分析結果

### Buffalo の失敗要因（5 件）

1. **単一メンテナ依存**: Mark Bates 個人への依存により、活動停止とともにプロジェクトが停滞
2. **Go カルチャーとの摩擦**: 独自 Context 型、非標準ミドルウェアが Go コミュニティの抵抗を招いた
3. **技術的負債**: Pop ORM（リフレクション依存）、Plush テンプレート、gorilla toolkit 依存
4. **gorilla toolkit アーカイブ事件**: 主要依存ライブラリの突然のアーカイブによる連鎖的影響
5. **Go 言語進化への追従不能**: ジェネリクス、net/http 改善への対応が困難な設計

### Beego の停滞要因（4 件）

1. **コントローラ継承パターン**: Go らしくない OOP スタイル
2. **リフレクション依存 ORM**: `init()` によるグローバル登録
3. **グローバル状態・シングルトンパターン**: テスタビリティの阻害
4. **ドキュメント言語障壁**: 英語ドキュメントの質の問題

### Broth のポジション

Go フレームワークを「薄い↔厚い」×「Go イディオム準拠度」の 2 軸で整理すると：

- **薄い + Go イディオム**: Chi, Echo, Gin（ルーターのみ）
- **厚い + Go イディオム違反**: Buffalo, Beego（失敗）
- **厚い + Go イディオム準拠**: **Broth**（空白地帯を狙う）

## 決定

Broth の設計原則 P1（Go イディオム最優先）は、Buffalo/Beego の全失敗パターンへの対策として機能することを確認した。

| Buffalo/Beego の失敗 | Broth の対策 ADR |
|---|---|
| 独自 Context | ADR-001（標準 context.Context） |
| DI コンテナ | ADR-002（コンストラクタ注入） |
| リフレクション ORM | ADR-003, ADR-D007（Bob コード生成） |
| 非標準ミドルウェア | ADR-001（net/http 互換） |
| グローバル状態 | ADR-002（明示的依存注入） |

## ガバナンスへの示唆

Buffalo の単一メンテナ依存を教訓に、以下を推奨：
- コアメンテナ最低 2〜3 名の確保
- 自動化されたリリースプロセス
- コントリビューションガイドの整備
